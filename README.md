# 3D-демо ЖК для встреч с застройщиками: Harizma (+ CRM), C1 и NRG Mirzo Ulugbek

Интерактивный 3D-макет реального строящегося дома, собранный **только из открытых данных** и без ручного 3D-моделирования:
дом на своём месте → этаж в разрезе → квартира со статусом → прогулка внутри → VR.

> ⚠️ **Не публиковать C1 и Harizma.** Поэтажные планы и статусы C1 — данные Murad Buildings (mbc.uz); планировки Harizma —
> каталог Golden House. Демо показывается локально с ноутбука. Выкладка по ссылке — только с согласия застройщика или за паролем.
> По ссылке выложен только NRG: https://spliti.uz/demo/ (старый адрес lab.edu-start.org/nrg-bi/ перенаправляет туда).

## Запуск

Все данные хранятся в бэкенде (Laravel, `backend/`, база SQLite) — фронт ничего не хранит и читает только API.
Два терминала:

```bash
cd backend && php artisan serve --port=8010
```

```bash
cd web && npm install && npm run dev
```

- Сайт Spliti: http://localhost:5180/ (`?lang=uz`)
- 3D-сайт ЖК: http://localhost:5180/demo/ (Harizma), `?p=c1`, `?p=nrg-mirzo-ulugbek` — или переключатель справа вверху
- CRM: http://localhost:5180/crm/

Адреса страниц те же, что на https://spliti.uz (см. "Выкладка: spliti.uz").

Vite проксирует `/api` и `/sanctum` в бэкенд (другой адрес — `BACKEND_URL=… npm run dev`). В приложении Claude это конфигурации
`zhk-crm-api` и `zhk-web`. Чтобы показать на телефоне в той же Wi-Fi-сети, откройте адрес из строки `Network:` Vite.

**Где какие данные:**

| Что | Где хранится | Как менять |
|---|---|---|
| ЖК: карточка, корпуса, этажи, геометрия, окружение, места рядом | база (`projects`, `block_layouts`, `floor_types`, `apartment_types`) + хранилище `media/` | пересобрать конвейером → `php artisan zhk:import <slug>` |
| Квартиры, статусы, цены, история | база (`units`, `unit_status_changes`) | CRM |
| Паркинг: уровни, места, статусы, цены, история | база (`parking_levels`, `parking_spots`, `parking_spot_status_changes`) | CRM, вкладка "Паркинг"; раскладка — `python3 -I tools/synth_parking.py` → `zhk:import` |
| Заявки покупателей / обращения застройщиков | база (`leads` / `inquiries`) | CRM / `php artisan spliti:inquiries` |
| Тексты, картинки сайта Spliti (RU/UZ) | база (`site_contents`) + `media/site/` | стартовые — `backend/resources/site/`, `php artisan spliti:site-import [--force]` |
| Контакты сайта, ссылка на демо | база (`site_settings`) | `php artisan spliti:site-set contacts.telegram spliti_uz` (без аргументов — показать) |

Пересобрать данные ЖК (после изменения скриптов или новых снимков) — конвейер пишет пакет для импорта в `data-build/`:

```bash
python3 -I tools/register.py     # совмещение планов этажей по лифтовому ядру → data-src/registration.json
python3 -I tools/build_api.py    # C1: снимки → data-build/ (≈30 с)
python3 -I tools/build_massing.py   # NRG Mirzo Ulugbek: корпуса, места рядом, тестовые планировки и шахматка
cd backend && php artisan zhk:import c1 nrg-mirzo-ulugbek     # в базу; статусы из CRM сохраняются
```

## Spliti — бренд и сайт (с 09.11.2026)

Продукт называется **Spliti** (split — разрез этажа + σπίτι — "дом"). Логотип собирается из геометрии: `python3 -I tools/brand.py`
→ `brand/*.svg` (знак, надпись, светлый/тёмный варианты, фавикон, превью `brand/sheet.html`) и `web/src/brand/geometry.ts` для Vue-компонентов
`SplitiMark` / `SplitiLogo`. Сайт Spliti — `web/index.html` (RU/UZ, `?lang=uz`): http://localhost:5180/. Тексты, картинки и контакты приходят
из бэкенда (`GET /api/site`), форма пишет в `POST /api/inquiries` (обращения: `cd backend && php artisan spliti:inquiries`).

## Harizma + CRM (с 09.11.2026): 3D-сайт с живыми статусами

ЖК **Harizma** (Golden House, Яшнабад, ул. Султанали Машхадий, 210). Здесь 3D-сайт берёт данные не из файлов, а из
**CRM** (`backend/`, Laravel 13): менеджер меняет статус и цену квартиры, сайт показывает это через ~20 секунд без перезагрузки;
заявка "Узнать цену" с сайта приходит в CRM с номером квартиры и этажом.

Запуск — как в разделе "Запуск" выше: 3D http://localhost:5180/demo/?p=harizma, CRM http://localhost:5180/crm/.
Вход менеджера: пароль задаётся/сбрасывается командой
`cd backend && php artisan zhk:admin admin@harizma.local --name="Менеджер продаж"` (без `--password` — сгенерирует и покажет).

**Первый запуск бэкенда с нуля:**

```bash
cd backend && composer install && cp .env.example .env && php artisan key:generate
touch database/database.sqlite && php artisan migrate --seed   # сид — только контент сайта Spliti
php artisan zhk:import harizma c1 nrg-mirzo-ulugbek     # из data-build; повторный импорт статусы CRM не трогает
php artisan zhk:admin admin@harizma.local --name="Менеджер продаж"
```

`--reset-statuses` у импорта возвращает тестовую стартовую шахматку (затирает статусы и цены из CRM — только для демо).

**Что в CRM:** сводка (в продаже / бронь / продано / снято, предложение в сумах, новые заявки) → шахматка корпуса
(этажи × квартиры, цвет по статусу, фильтр) → карточка квартиры (чертёж типа, статус, цена, комментарий, история "кто, когда,
было → стало") → смена статуса пачкой (Shift-клик, "Выбрать несколько" или номер этажа — весь этаж) → заявки с сайта
(новая / в работе / закрыта) → лента изменений. Цена проданных квартир на сайт не уходит — остаётся в CRM.

**Откуда данные Harizma и что условно:**

| Что | Откуда | Условно |
|---|---|---|
| Корпуса | 9 контуров секций OSM на участке | этажность 16/12 — по госреестру (объект 976), какая секция какой высоты — условно; в OSM 9 из 17 корпусов, дома 5 и 8 третьего этапа не показаны |
| Планировки | 8 реальных типов из каталога Golden House 2025 (стр. 36–37): чертёж в карточке, площади комнат, стены для прогулки извлечены из чертежа | масштаб чертежа подобран по площади; **расстановка квартир на этаже условная** — поэтажных планов застройщик не публикует |
| Статусы и цены | стартовая шахматка 753 квартиры — **тестовая** (жёлтая плашка) | дальше ведутся в CRM; ~15,4 млн сум/м² — не цена застройщика |
| Фасад | палитра по рендерам с gh.uz | сетка окон стилизована |
| Окружение и места рядом | OSM + логотипы брендов | — |

Пересобрать данные Harizma: `python3 -I tools/apartment_types.py && python3 -I tools/build_harizma.py`, затем `php artisan zhk:import harizma`.
План работ: [plans/2026-11-09-plan-01-harizma-crm.md](plans/2026-11-09-plan-01-harizma-crm.md).

## Атмосфера и солнце (с 12.11.2026)

Нижняя панель 3D-сайта: **сезон** (зима/весна/лето/осень = солнце на 21 дек / 21 мар / 21 июн / 23 сен + ландшафт:
листва, цветение, снег), **погода** (ясно, облачно, дождь, снег — облака, осадки, туман, мокрый асфальт), **время 0–24**
с автопрокруткой суток и **путь солнца** над домом. Ночью горят окна (доля — по часу), окна соседних домов, фонари,
в прогулке — светильники в квартире. Всё процедурно на three.js (`web/src/scene/atmosphere.ts`), без текстур и серверов.

Солнце: позиция — `web/src/domain/sun.ts` (алгоритм NOAA + рефракция, восход/закат по верхнему краю диска);
часы солнца в окнах — `Engine.sunHoursFor`: точки окон по краям и середине фасада квартиры, луч к солнцу против
окружения OSM, корпусов ЖК и стен самого здания, шаг 5 мин с уточнением границ до ~20 с. Карточка квартиры показывает
интервалы солнца на полосе от восхода до заката.

## Паркинг (с 12.11.2026)

У ЖК с корпусами (NRG, Harizma) — подземный паркинг на 2 уровня. **Тестовый**: планов застройщика в открытом доступе нет, раскладка,
статусы и цены условные, на сайте и в CRM это подписано. План и решения: [plans/2026-11-12-plan-06-parking.md](plans/2026-11-12-plan-06-parking.md).

- **3D:** знак "P" у въезда и карточка "Паркинг" в панели ЖК открывают режим паркинга — на ровном тёмном фоне только выбранный уровень:
  колонны, ядра лифтов в корпуса, рампа, места цветом статуса, машины на проданных местах, стойки у мест с зарядкой; свет свой, одинаковый днём и ночью. Переключатель уровней со свободными местами, фильтр по типу (обычное, широкое, с зарядкой, для маломобильных)
  и "только свободные", карточка места (размер, площадь, цена, ближайший лифт в корпус) и заявка на место. Статусы обновляются
  вместе с квартирами, раз в 20 секунд.
- **CRM:** вкладка "Паркинг" — план уровня (SVG), карточка места со статусом, ценой, комментарием и историей, выбор пачкой
  ("Выбрать несколько", "Весь уровень"); в заявках видно место.
- **Бэкенд:** модуль `app/Modules/Parking` (действия в `Application`, ответы — `JsonResource`), публичный
  `GET /api/projects/{slug}/parking` (контракт в `backend/docs/public-api.md`), заявка — `POST /api/leads` с `parking_spot_id`.
- **Данные:** `python3 -I tools/synth_parking.py nrg-mirzo-ulugbek harizma` → `data-build/projects/<slug>/parking.json`
  (≈ 0,55 места на квартиру, 2 уровня, ядро у каждого корпуса рядом с паркингом, рампа у торца, ближайшего к улице),
  затем `php artisan zhk:import <slug>` — статусы и цены из CRM при повторном импорте сохраняются. На сервер паркинг попадает
  при `infra/deploy.sh --init`.

## Сценарий показа на встрече (3 минуты)

1. **Дом на своём месте.** Башня на реальном участке у перекрёстка, рядом семиэтажки с Махтумкули, канал Салар, эко-парк Бобура.
   Ползунок времени внизу двигает солнце и тени: "вот так дом освещён в 9 утра в декабре".
2. **Этаж.** Клик по этажу (или по рейке слева) — этаж срезается, квартиры подсвечены по статусу из вашего каталога.
3. **Квартира.** Карточка: площадь, этаж, высота окон, стороны света, **что видно из окон** (по карте), **часы солнца** на выбранную дату с учётом соседних домов.
4. **Прогулка.** "Пройти по квартире" — WASD и мышь, на телефоне джойстик. За окном — реальное окружение на высоте этажа.
5. **Главная фраза:** "Это собрано без ваших файлов — по картинкам с вашего сайта. С DWG-чертежами будет точнее, плюс отделка, мебель, вид с дрона и живые статусы из CRM".

## Что условно для NRG Mirzo Ulugbek

- Высоты этажей: 1-й — 3,6 м, остальные — 3,0 м; фасад стилизован (сетка окон), не "неоклассика" как в жизни.
- Этажность по OSM; у блока 26/13 в 2ГИС указано 4 этажа, в OSM — 5.
- Данные 2ГИС не выгружались (условия сервиса запрещают копирование) — ЖК опознан по странице, геометрия и места — из OSM.
- Время пешком = расстояние × 1,25 / 80 м в минуту, без маршрутизации.
- Двор и тротуары (у всех ЖК): плана благоустройства в открытых данных нет — двор вымощен целиком, газоны с деревьями
  раскладываются автоматически в свободных местах (`src/scene/landscape.ts`), внутриквартальные проезды OSM уходят под плитку;
  ширина тротуаров — по классу улицы (`SIDEWALK` в `src/scene/context.ts`), деревья — у бордюра, на проезжую часть не встают.

## Что условно для C1 (честно говорить, если спросят)

- Высоты этажей: 1-й — 4,8 м, подиум — 4,2 м, жилые — 3,3 м (разрезов нет).
- Фасад стилизован по рендеру застройщика; чертежей фасада нет.
- Стены извлечены автоматически из картинок планов, возможны мелкие неточности. Подписи площадей — для комнат до 38 м²; объединённые кухни-гостиные показываются одной цифрой.
- Соседние дома — упрощённые объёмы OSM; у части высота оценена по типу здания.
- Цена — "по запросу", как у застройщика: выдумывать нельзя.
- 3 этаж показан по плану 4-го (план 3-го не снят), 1 этаж — по плану 2-го.
- VR (WebXR) не проверен на реальном шлеме — шлема нет.

## Как устроено

```
backend/    Laravel 13 (модульный монолит): Catalog (ЖК, корпуса, типы, квартиры, импорт), Sales (статусы, цены, история),
            Leads (заявки), Identity (вход менеджера — сессия Sanctum), Inquiries (обращения с сайта Spliti);
            SQLite для демо, тесты: php artisan test
data-src/   снимки источников на 04.11.2026 (см. SOURCES.md) — НЕ публиковать
tools/      planlib.py (растровая морфология без OpenCV), register.py (совмещение этажей), extract_floorplan.py (план → геометрия), build_api.py
data-build/ пакет для импорта в бэкенд, который пишет конвейер (tools/); фронт его не читает. Контракт API — backend/docs/public-api.md
web/        Vite + Vue 3 + TypeScript + three.js; три точки входа: index.html (сайт Spliti, /), demo/index.html (3D, /demo/), crm/index.html (CRM, /crm/)
  src/domain  типы, статусы, суммы, солнце, стороны света, вид из окон
  src/api     клиент /api
  src/scene   движок: окружение, здание, разрез, прогулка, VR
  src/ui      интерфейс
```

**Конвейер "картинка плана → 3D":** маска стен по цвету → сетка 5 см → снятие дуг дверей и теней значков
(открытие 2×2, только прямые участки, сплошные блоки шахт) → контур перекрытия (закрытие разрывов + заливка) →
стекло по линиям окон → дверные перемычки по форме → комнаты как связные области → прямоугольники в метрах.
Масштаб — по площадям квартир каталога, совмещение этажей разных типов — корреляцией по лифтовому ядру.

**Вес:** весь первый экран (JS, CSS и все данные дома с окружением) — около 1 МБ, 277 КБ в gzip.
Рендер — на устройстве, без серверных видеокарт.

## Выкладка: https://spliti.uz (с 10.11.2026)

  (proxy host `spliti.uz`, `www.spliti.uz` → `http://172.17.0.1:18095`, Let's Encrypt). `www` шлюз перенаправляет на `spliti.uz`.
- Команды artisan на сервере: `cd /home/projects/spliti/infra && docker compose exec -u www-data app php artisan <команда>`
  (например `spliti:inquiries`, `spliti:site-set`, `zhk:admin`).
