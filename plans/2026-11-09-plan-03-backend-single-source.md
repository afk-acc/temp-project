# План 03 — бэкенд как единственный источник данных

**Статус:** ✅ сделано и проверено локально 2026-11-09 (на сервер не выкладывалось)
**Запрос владельца:** «нужно сделать бэкенд, если его ещё нет, чтобы все данные хранились там».

Бэкенд (Laravel, `backend/`) уже есть: ЖК, корпуса, квартиры, статусы, история, заявки, обращения. Мимо него до сих пор живут:

| Что | Где сейчас | Куда |
|---|---|---|
| Тексты сайта Spliti (RU/UZ), вопросы, цифры, картинки | `web/src/site/i18n.ts`, `img/` | таблица `site_contents` + файлы в хранилище бэкенда, `GET /api/site?lang=` |
| Контакты сайта и ссылка на демо | `web/src/site/config.ts` | таблица `site_settings`, команда `spliti:site-set` |
| Данные 3D-сайта в режиме по умолчанию | Vite-заглушка читает `api-stub/*.json` | заглушка удаляется, фронт всегда ходит в API (прокси Vite → Laravel) |
| Выкладка NRG на lab.edu-start.org | копия `api-stub` | выгрузка из базы: `php artisan zhk:export` |
| «Как собран макет» в окне «О данных» | зашито во фронт (у Harizma показывался текст NRG) | поле `about` в данных проекта |
| Тип этажа подиума C1 | `'POD2'` в движке | первый этаж из данных проекта |

## Решения

1. **Источник правды — база.** Файлы из конвейера чертежей (`api-stub/` → переименовать в `data-build/`) — только пакет для импорта, как сид; фронт их больше не читает.
2. **Контент сайта — JSON в базе по языкам**, стартовые значения — `backend/resources/site/` (импорт не затирает правки в базе без `--force`).
3. **Картинки сайта** — в хранилище бэкенда, отдаются `GET /api/site/media/{file}`; ссылки на них — в контенте.
4. **Статическая выкладка** остаётся возможной, но собирается выгрузкой из базы, а не из файлов конвейера.
5. Во фронте остаются только код и оформление: вёрстка, компоненты, токены, геометрия логотипа, декоративный дом на первом экране.
