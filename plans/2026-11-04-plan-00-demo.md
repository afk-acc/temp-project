# План 00 — демо 3D-макета реального ЖК для встреч с застройщиками

**Статус:** ✅ демо собрано и проверено 2026-11-04 (кроме VR на реальном шлеме — за владельцем)
**Связано:** отчёт `ai-projects/reports/3D-макет и VR для новостроек Узбекистана.md`, раздел 8, этап 0.
**Цель этапа:** показать застройщику его же дом, собранный из открытых данных:
«вот ваш дом на своём месте, вот этаж, вот квартира, по ней можно пройти — хотите так по вашим чертежам?».
**Критерий готовности:** демо открывается локально; первый экран меньше 10 МБ и работает в мобильном виде;
сценарий «дом → этаж → квартира → прогулка» проходит без ошибок в консоли.

## Решения

1. **Данные — за API-контрактом, фронт ничего не хранит.** На этапе 0 бэкенд заменяет `api-stub/`:
   JSON-файлы, которые генерирует `tools/build_api.py` из снимков источников. Vite отдаёт их по `/api/...`.
   На этапе 2 тот же контракт реализует Laravel-модуль; фронт не меняется.
   **Почему не Laravel сейчас:** этап 0 проверяет спрос, а не нагрузку. Контракт фиксируется сейчас (`api-stub/CONTRACT.md`).
2. **Геометрия из картинок планов — скриптом, а не руками.** Цвет стен → маска → прямоугольники в метрах.
   Двери и окна — разрывы маски, закрытые морфологией; комнаты — связные области.
   Это прототип будущего конвейера «DWG → 3D» из отчёта (п. 2.4), только на растре.
3. **Масштаб** — по площадям квартир: Σ площадей из каталога ÷ Σ площадей контуров в пикселях.
   **Выравнивание этажей разных типов** — по габариту башни (внешний контур стен).
4. **Стек:** Vite + Vue 3 + TypeScript + three.js (императивная сцена в модуле `scene/`, UI — Vue).
   Без пиксельного стриминга, всё считается на устройстве.
5. **Квартиры в прогулке — white box**: стены, пол, потолок, настоящий вид из окна на окружение OSM, площади комнат на полу.
   Работает для всех квартир автоматически. Мебель — только если останется время, на 1–2 витринных квартирах.
6. **Цены в сумах** (закон «О рекламе», ст. 16). Поле цены необязательное; у C1 — «по запросу».

## Форсайт

- **Контракт API = будущие таблицы:** `projects`, `buildings`, `floor_types` (геометрия JSON), `floors`, `units`, `unit_status_observations`.
  Статусы с `observed_at` и `source` — та же модель «у факта есть источник и дата», что в UyPuls.
- **Геометрия в локальных метрах** от точки госреестра; азимут здания хранится отдельно. Значит, тот же формат подойдёт для DWG-конвейера.
- **Типы этажей отдельно от этажей:** 30 этажей ссылаются на 8 типов. Геометрия не дублируется, сцена переиспользует меши.
- **Нестандартные этажи** (подиум 2–5, терраса 6) — отдельные типы с ручным выравниванием, если автоматическое по габариту не сработает.
